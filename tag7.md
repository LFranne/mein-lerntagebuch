\# Tag 7



\*\*Was gelernt?\*\*

In dieser Woche habe ich den kompletten Git/GitHub-Workflow einmal von

Anfang bis Ende durchlaufen: ein Repository klonen, Dateien anlegen,

Änderungen mit add/commit/push sichern, einen Branch erstellen und über

einen Pull Request wieder in main zusammenführen. Aus einzelnen, am Anfang

noch unsicheren Befehlen ist inzwischen eine Routine geworden.



\*\*Welches Problem?\*\*

Am Anfang war mir vieles noch fremd — vom Umgang mit dem Terminal über die

Frage, wo ich mich gerade im Ordner befinde, bis hin zu Branches und Pull

Requests. Es gab auch kleine Stolpersteine unterwegs, z. B. dass der

"Compare \& pull request"-Banner auf GitHub irgendwann verschwindet.



\*\*Wie gelöst?\*\*

Indem ich Schritt für Schritt vorgegangen bin und mir nicht zu viel auf

einmal vorgenommen habe. Für jedes Problem gab es einen alternativen Weg

(z. B. den Pull Request manuell über den Reiter "Pull requests" erstellen)

— das hat mir gezeigt, dass es bei Git meist mehrere Wege zum Ziel gibt.
